perf: add t73 global-index recursion + spec（第四轮-自维护index）

【为什么】用户在"三种递归隔离方式"中预判"自维护全局 index（不用 setlocal、不用 for-var）
应该第三种最快"。其直觉是：省掉 setlocal 的环境表复制、也省掉 for 循环域的管制，只用一层
全局计数器拼唯一变量名就应最省。但这个预判需要实证——因为"拼名"+"间接读"（call set 双解
引用）本身可能藏有隐性税。若预判成立则 MAL 可据此换架构；若不成立，就必须找到问题在哪，
这正是 t73/t74 一组的本意。

【怎么改】新增 t73_rec_global.cmd：`:rec` 首行 `set /a _G.IDX+=1` 取全局帧号；`set "_nm=
_I!_G.IDX!.v"` 拼出本帧唯一变量名，`set "!_nm!=1"` 直接写入；读回走 `call set "_t=%%!_nm!%%"`
双解引用间接读并累加 _SUM；`_g=%~1-1` 降层递归，出层 `_G.IDX-=1` 释放帧号。全程一个全局
计数器，无 setlocal、无 for。附 t73.spec.md 记录接口与"间接读对含 ~/( 字面值有缺陷"的边界。

【风险与验证】正确性出口 `SUM=_D` 校验通过。实测 D=200 时 10118µs/步，是基线 t70 的 2.68
倍、也是五者中最慢——**预判被证伪**。根因是"拼 名+间接读"两趟开销叠加，尤其 call set 双解
引用重。这一结果反向证明了 t74"只写不读、数据走参数"才是全局 index 思路的可行形态，为
README 3.7 结论"不要用全局 index 做帧局部"提供数据。
