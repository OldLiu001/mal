perf: add t74 global-index write-only + spec（第四轮-只写不读）

【为什么】t73 证明"自维护全局 index + 间接读"是所有方案里最慢的（2.68x），但马上要回答一个
追问：慢的到底是"自维护 index 拼名写"本身，还是叠加的"call set 间接读"？只有把"读"从帧局部
里彻底拿掉、让数据改走调用参数，才能把两笔账剥开。这决定 MAL 解析器遇到"帧局部数据型字段"
时，是彻底放弃全局 index，还是退而采用"写法稍绕但更快"的只写形态。

【怎么改】新增 t74_rec_global_noread.cmd：`:rec` 首行 `_G.IDX+=1`；`set "_I%_G.IDX%.x=1"`
拼名直接写入而已（**只写、不读帧局部**）；降层信息走调用参数 `_g=%~1-1`、帧返回累加走
`_s=%~2+1`；出层 `_G.IDX-=1`。整个递归不再有任何 call set 间接读，累加结果由最深层经参数
逐层回传至首层 `_SUM`。附 t74.spec.md 记录接口与"规避间接读缺陷"的边界说明。

【风险与验证】正确性出口 `SUM=_D` 校验通过。实测 D=200 时 4555µs/步，约基线 t70 的 1.21x，
较 t73 的 2.68x 大幅回落——确证"间接读"才是全局 index 最大的税，拼名直写本身近乎免费。
但即便只写形态也仍比 .for-var 域（1.11x）慢约 8%，故 README 3.7 结论：全局 index 不值得替代
.for-var，仅"纯数据型字段"可作降级思路。
